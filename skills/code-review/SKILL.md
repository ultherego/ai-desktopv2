# Przegląd kodu — tylko odczyt

- Analizuj zmianę wraz z jej rzeczywistymi wywołaniami i testami.
- Szukaj błędów poprawności, utraty danych, wyścigów oraz naruszeń uprawnień.
- Dla każdego wyniku podaj priorytet, warunek wystąpienia, skutek i miejsce w kodzie. Unikaj duplikatów.
- Oddziel potwierdzony defekt od hipotezy wymagającej sprawdzenia.
- Nie zastępuj brakujących testów zapewnieniem o poprawności. Podaj konkretną lukę w dowodach.
- Nie zmieniaj plików. Skill nie nadaje dodatkowych narzędzi, uprawnień ani zgody na wysyłanie danych.
