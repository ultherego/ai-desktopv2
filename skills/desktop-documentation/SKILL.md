# Desktop configuration with evidence

## Identify the environment

Establish the name and version of the running desktop or compositor, the session type and the exact symptom. Rely on the available session data, program version or the user's answer; an installed package alone does not prove it is currently running. Keep the active session separate from the set of installed environments; several can coexist. Treat desktop shells and panels such as DMS as separate components, not as synonyms for a compositor. Check whether the problem concerns configuration, an output device, one application or the whole session.

Commands run by AI Desktop usually have no graphical session or user sockets. An error connecting to IPC, Wayland or a user service then means no visibility. Do not treat it as evidence of a failure and do not propose a restart. When such an observation is essential, state exactly what is missing; do not change permissions or the execution mode to get around the limit.

## Choose the documentation and file

1. Choose the documentation of the right program and installed version. An option from the current documentation branch may not exist in an older release.
2. Read the actual configuration and its included files only within the allowed scope. Establish whether the file is generated by another tool. A fix in a generated file can disappear at the next write.
3. For a syntax error, find the indicated line and the option's definition. For a behavior error, check the order of rules and their match conditions. Do not carry syntax between compositors.
4. If online documentation is unavailable, use the local documentation supplied. Without either, mark the proposed option as unverified; do not present the model's memory as a current source.

## Change and test

Propose the smallest change that addresses the symptom and preserve the previous content. A write needs a diff and the controller's consent. Use the right program's validator only when the exact command is allowed and will check the right file; e.g. niri offers `niri validate`. The AI Desktop `text` check confirms only UTF-8, not the correctness of KDL configuration or desktop rules.

A passing parser confirms the syntax, not the working of a shortcut, monitor or rule. Reproduce the original symptom after a safe application and compare the result. A reload or session restart is a separate state change; do not end the user's session as part of diagnostics. On undo, restore only your own change, keeping later edits.

## Result

Give the environment and version, the file and source used, the evidence for the cause or a hypothesis, the scope of the check and the write state. When missing session visibility or a missing validator blocks you, end at that specific gap.
