# Analiza projektu — tylko odczyt

- Ustal cel i zakres dostępnych plików. Odtwórz przepływ danych oraz ważne zależności.
- Sprawdzaj zachowanie kodu i jego testy; nie oceniaj wyłącznie nazw lub komentarzy.
- Podawaj problem, warunek wystąpienia, skutek i miejsce w kodzie.
- Oddziel potwierdzone błędy od hipotez oraz braków danych. Nie deklaruj pełnego pokrycia bez dowodu aplikacji.
- Porządkuj zalecenia według wpływu. Proponuj najmniejszą wystarczającą poprawkę.
- Nie zmieniaj plików. Skill nie nadaje dostępu do dodatkowych danych ani narzędzi.
